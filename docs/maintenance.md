# 目录与维护约定

## 仓库内容

| 位置 | 用途 |
| --- | --- |
| `src/`、`public/` | 网页程序、静态资源与公开配置 |
| `signal/` | 配对和加密转发 Worker |
| `deployment/` | 正式版固定提交 |
| `scripts/` | 构建与公开文件检查 |
| `tests/` | 按功能分组的回归检查及显式运行的性能基准 |
| `docs/` | 当前功能、部署和技术边界 |

测试、文档、开发依赖和基准结果不进入网页下载。测试代码多于源码并不等于网页体积大；应以构建产物和运行情况判断。测试重点保留原文件完整性、存储清理、恢复竞态、浏览器能力回退及认证隔离，不按行数机械删减。

## 核心职责

| 模块 | 职责 |
| --- | --- |
| `protocol.ts` | 统一公开入口，供外部调用和协议回归使用 |
| `transfer.ts` | 文件分块、校验、接收保存与传输检查点 |
| `signaling.ts` | 配对服务连接、认证消息队列及连接生命周期 |
| `auto-pair.ts` | 自动配对、直连／加密转发选择与恢复协调 |
| `protocol-codec.ts` | 配对码编码、消息加解密和字节编码 |
| `app-view.ts`、`main.ts` | 页面模板与界面事件、会话入口 |

实现模块直接依赖所需模块，不通过公开入口反向导入；存储模块只导入文件信息类型。结构整理保持协议、分块大小、超时策略和加密参数不变，依靠既有完整性与连接恢复检查验证行为。

## 发布

- **测试服快发**：完成构建、公开文件检查和与本次改动相关的必要检查即可更新 `/test/`。不重复等待本地与远程两套完整回归；全套检查可在后台继续。发现失败要记录并修复，不能将该版本提升正式版。
- **正式版完整验收**：用户确认提升后，等待目标提交的完整检查通过，核对生产／测试隔离与相关实机结果，再修改 `deployment/production.json`。检查不通过不得提升。
- 前端和 Worker 分别部署。源码变化并不代表云端配置、密钥或订阅已变更。

## 文档与测试

已有主题优先更新原页，新测试放入对应功能目录。删除废弃功能时删除其专用成功用例，保留防止旧接口重新启用的拒绝测试。相同组件的小型测试合并，避免继续使用日期或某次审查作为文件名。

一次性实验和原始结果放在仓库外或 Git 忽略目录；性能基准按需运行，不能将本机数字当作公网速度保证。过程追溯使用 Git 提交和 PR，不再持续增加 `review-日期`、`restoration` 等文档。
