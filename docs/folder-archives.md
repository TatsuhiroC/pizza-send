# 直接选择文件、文件夹打包与清空选择

2026-10-18，基于已发布主分支 `a20d336`。用户已批准合并并发布本轮改动；以下记录发布前的实现与验证范围。

## 用户可见行为

- 点击发送区域直接打开系统的多文件选择窗口；删除之前的“文件／文件夹”二选一弹窗、隐藏目录选择器及对应样式、文案。
- 电脑上可将文件和文件夹一起拖入。普通文件保持原样；每个顶层文件夹生成一个独立的 `文件夹名.zip`。
- ZIP 使用 STORE（压缩级别 0），不试图缩小内容，保留 UTF-8 根目录名称、子目录、空目录、文件名和文件内容。接收后需要解压；没有实现接收端自动解压到本地目录。
- 例：`番茄炒鸡蛋.zip` 内有 `番茄炒鸡蛋/番茄.txt`、`番茄炒鸡蛋/鸡蛋.txt`，不再变成两个散落的文件。
- 文件列表上方增加“清空已选文件”按钮。单次点击清空所有选择、取消正在进行的打包，并清理已生成的源 ZIP；传输中不允许清空。清空后可以重新选择相同文件。
- 打包期间有进度和取消按钮，不允许以尚未打包完整的文件开始分享。失败不会把部分目录内容降级为散文件发送。

## 实现与兼容性

发送端使用固定版本 `@zip.js/zip.js` 2.24.0，在单个专用 Worker 中逐项打包，读取块为 256 KiB，输出直接写入 OPFS 同步文件句柄；不将整个大文件或完整 ZIP 收进数组。写盘处理短写；原文件读取有 15 秒单块超时和长度核对。ZIP64 由库按需生成，避免 ZIP 标准格式的 4 GiB 偏移限制。

不增加协议版本或配对服务接口。ZIP 作为一个普通文件进入已有 DTLS、SHA-256、逐字节进度、多人分享、断线恢复及保存流程，因此旧接收页面也可以接收。慢网的可选压缩仍是既有的独立功能。

新 Worker 只在需要打包时下载。压缩引擎、远端资源、额外 Worker 和 WASM 均未启用，CSP 不需要放宽。Vite 启动时预发现这个延迟模块的依赖，避免开发环境首次打包触发依赖优化、刷新页面并丢失选择。

网页不能控制系统窗口实现文件和目录混选。此次点击入口只选文件，目录通过桌面拖放导入；没有宣传成一个能在系统窗口里任意选择文件与目录的入口。

若 OPFS 不存在或实际访问被拒绝（包括部分无痕环境），明确提示先在系统中压缩文件夹，再选择 ZIP。没有为大文件夹提供整包内存回退。iPhone Safari 不能由网页任意创建“文件”App 中的本地目录；保存 ZIP 后，可在“文件”中解压。桌面 Chrome/Edge 可以在用户授权目录后实现自动解包，但本轮没有加入该能力。

## 空间与清理

STORE ZIP 仍需要读取全部内容并写出一份文件，CPU 消耗较低，不是零耗时或零空间。发送端需要约等于文件夹大小的额外磁盘空间；预先估算额度，真实写盘发生额度不足时也会失败并清理。文件夹打包模块仍受浏览器可用空间限制，没有承诺 10/20 GiB 在所有设备上可用。

源 ZIP 放在本站 OPFS 的 `pizzasend-source-archives-v1/<随机批次>/`。原文件不修改。ZIP 在仍被选中时保留以支持再次分享及多人发送；移除对应选择或清空全部时删除。页面关闭会终止 Worker，下一次打开本站清理遗留批次；其他标签页正在使用的批次由 Web Lock 保护，不会被清理。关闭网页后不能保证立即回收占用。接收端既有的 10 分钟暂存规则保持不变，不能把它误写成源 ZIP 的期限。

## 边界与安全

每次拖入最多 100 个原文件、1000 个文件／目录条目，目录深度最多 32 层，单路径最多 4096 UTF-8 字节。选择列表仍最多 100 个待传文件（每份 ZIP 作为一个文件）。空目录可以单独发送。超限整体报错，不截断或丢掉目录。

逐段拒绝 `.`、`..`、斜线、反斜线、冒号及控制字符；Worker 再验证根目录、父目录、深度、重复／冲突路径和总大小。遇到不能安全保留的名称时报错，不静默改写路径。ZIP 保留普通文件内容和目录结构，不承诺保留符号链接、所有权、平台权限等文件系统属性。

依赖许可随网站提供：[zip.js BSD-3-Clause](../public/licenses/zip-js.txt)。

## 验证

最终检查：构建及配对服务 dry-run 通过；Chromium **211 项通过**，WebKit **59 项通过、8 项既有环境限制跳过**，正式响应头检查 **9 项通过、1 项既有环境限制跳过**。合计 **279 项通过、9 项跳过**，无失败。新增文件夹打包检查在两种引擎中全部执行并通过。

正式构建另在原有 CSP 下实际打包并清空源 ZIP；中英文 390/320 px 四种布局均无横向溢出、无 CSP 违规。预览截图及机器记录保存在仓库外的 `outputs/pizza-send-folder-preview/`。完整回归还实际完成 1 GiB 普通文件传输与独立校验；该结果不等同于已验证 1 GiB 文件夹打包速度。

新增的针对性检查包括：

- 直接系统多文件选择、多次追加、再次选择同一个文件、320 px 布局及中英文。
- 中文根目录、嵌套同名文件、空目录与普通文件混合打包；Chromium 实际 WebRTC 传输、下载后以 Python 标准库独立读取 ZIP、核对 STORE 方法、路径与每份内容的 SHA-256。
- WebKit 使用独立临时普通浏览配置，实际生成 OPFS ZIP 并读取验证目录及内容；默认无痕自动化配置会拒绝 OPFS，未以跳过核心打包测试代替验证。
- 实际 8 MiB 源文件的 Worker 读写监测：单次读取和写出均不超过 256 KiB；另独立核对超过 4 GiB 的 ZIP64 原始偏移字段。这不是一份实际 10/20 GiB 文件夹打包测试。
- 取消后保留之前选择；清空全部时取消新的打包且不会复活选择；关闭后下一次打开清理；其他标签页打开时保留正在使用的 ZIP。
- 额度不足、OPFS 接口缺失、接口存在但被拒绝，以及路径穿越／重复名称时正确失败，无半份分享。

独立 WebKit 检查不能代表已验证真实 iPhone Safari 的全部系统保存行为。
