# 启动配置与源文件读取保护 · 2026-10-24

基于已发布主分支 `1481c73`。维护者已授权完成检查后提交、合并并发布。本次处理审查中的启动配置竞争、源文件读取等待边界和开发依赖公告；不加入连接预热、预检缓存或多文件并行检查，不修改配对 Worker、服务配额或域名。

## 配置就绪与重试

此前默认配对地址为空，配置文件尚未返回时，发送入口就可能误把“未加载”当成“手动配对”。配置请求一直不结束，也会挡住分享链接的自动接收。

现在发送、连接和扫码入口等待配置就绪；文件仍可先选。配置请求包括读取响应正文在内设八秒截止，失败显示可重试的提示，保留已选文件和原接收邀请。重试成功后，原邀请可继续连接，无需重新扫码。用户在等待期间编辑或粘贴了另一邀请，则保留新的选择，不在配置返回后连接旧地址。

已明确保存的自定义服务或手动配对选择，在公共配置不可用时继续有效；也可以通过连接设置恢复。没有硬编码一个未知的备用配对域名，也不把默认加载失败静默切成手动模式。新提示同时提供中英文。

## 源文件读取截止与取消

此前创建前首尾预检查和目录打包已有读取截止，但发送分块、恢复时重算前缀以及可选压缩采样使用了无截止的默认读取。

现在默认单次分块读取设十五秒截止。它限制的是一次迟迟不返回的磁盘／文件提供者操作，不是把整个大文件传输限制为十五秒。实际数据块、文件散列和接收确认格式不变。

结束传输、替换网络通道或取消文件预检查，会中止应用对旧读取的等待。浏览器的原生 `Blob.arrayBuffer()` 不能被真正撤销；底层操作迟到返回或拒绝时仍有处理器接住，不能继续向旧会话发送数据、覆盖新选择或造成未处理拒绝。可选压缩采样也使用所属通道的取消信号。

保留既有后台宽限：已知页面在后台时不会仅因新的十五秒读取截止而提前失败，返回前台后，尚未返回的读取获得新的十五秒窗口。取消仍立即生效。

新增真实收发回归还复现了一个相关顺序问题：接收者得知源文件读取失败后退出，成员列表可能先于错误通知确认返回。现在在既有、有界的错误通知宽限中保留已知失败原因，避免被“接收者已退出”覆盖；不延长该宽限或保留无界重试。

## 开发依赖修补

当前唯一的 Undici 依赖链是 `wrangler → miniflare → undici`。使用临时 npm override，将实际安装与锁定版本从 7.29.1 修补到 7.30.1；不降级 Wrangler，也不更新无关依赖。锁文件只修改该包的版本、下载地址与完整性校验三项。

从锁文件重新执行安装后，实际依赖树确认修补版已生效；npm audit 对生产和开发依赖的已知漏洞报告均为零。该客户端属于开发工具，不进入浏览器包；这不是对所有环境或浏览器安全性的保证。后续升级 Wrangler／Miniflare 时，应重新评估并在上游已修补后移除此 override。

官方公告：[Undici 安全说明](https://github.com/nodejs/undici/security/advisories/GHSA-xjj6-f33q-929c)、[7.30.1 发布说明](https://github.com/nodejs/undici/releases/tag/v7.30.1)。

## 验证

修改前，旧代码在“配置未就绪却允许发送”和“默认源读取没有截止”回归中失败。新增覆盖：

- 配置挂起、加载失败、无效 JSON、截止与重试、原文件选择保留、旧响应迟到、接收链接重试，以及加载期间用户改变邀请。
- 明确保存的自定义／手动设置、失败后通过设置恢复，保持中英文一致。
- 分块读取截止、立即取消、旧通道读取结束后新通道仍可发送、后台宽限与返回前台，以及已知源错误不被退出通知覆盖。
- 真实 WebRTC 的源文件读取挂起，验证双方显示可理解的源错误，没有把不完整文件提供为下载；实体设备场景不以此自动化冒充。

本地生产构建、TypeScript 严格检查、配对 Worker 部署干跑、全依赖安全扫描均通过。实际收发、多人分享、连续恢复、后台返回、原名／SHA-256、流控、邀请就绪、粘贴、扫码过渡、WebKit 以及生产构建安全策略的相关回归已通过。需要真实 WebRTC 的 WebKit 场景按既有引擎覆盖由 Chromium 执行，不计为 WebKit 通过。全套 CI 与正式发布以本次 PR 和部署回执为准。

为检查新增保护的开销，在同一隔离 Chrome 交替读取同一合成本地 16 MiB 文件，按 32 KiB 分块，每个版本六次。首版保护中位数约 141.2 → 150.1 ms；减少每块等待的 Promise 分配后，最终一轮约 133.7 → 137.8 ms，约多 4.2 ms（3.1%）。两轮基线本身有波动，不能将差值当成固定性能承诺。这只是源 I/O 开销对照，不是公网传输基准；本次目标是正确性与故障退出，不宣称提高公网传输速度。

没有创建公共预览域名，也没有改变默认 Worker 入口关闭状态、免费配额、文件转发或 TURN 设置。合入后仅由既有 Cloudflare Pages 流程更新前端。
