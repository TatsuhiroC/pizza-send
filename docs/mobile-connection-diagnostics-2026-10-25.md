# 移动数据极慢：只读诊断

状态：默认关闭的调查工具；尚未确认用户实际 3 KB/s 的根因。基于已恢复独立语言功能的主分支 `108f0fc`，传输算法继续保留 10 月 21 日实现。

## 为什么需要记录

Wi-Fi 可以达到约 18 MB/s，而移动数据只有约 3 KB/s，说明必须调查两种网络下实际使用的连接和处理过程。当前网页没有保留过去传输的详细记录，事后无法从界面上的一个平均速度还原瓶颈。Chrome 的内部诊断页面也不在当前浏览器工具允许访问的范围内，不能借助其他接口绕过这个限制。

已完成的隔离实验支持“可靠有序传输对丢包敏感”这一排查方向，但不证明用户的运营商存在相同丢包。人工慢读取也能复现低速；不能只看速度就判断是网络、手机或代码。该工具的用途是收集区分这些机制的证据，不是速度修复。

## 开关与范围

- 仅在打开带 `?connection-debug=1` 的网页时启用；普通链接不采样、不启动诊断定时器、不显示诊断面板，也不附加诊断计数。
- 诊断发送页生成的链接保留此参数。接收端直接打开该链接也会启用诊断。已经打开的普通扫码页或粘贴页不会因为解析链接而自动启用；单端启用仍可记录本端。
- 页面底部显示“连接诊断（仅本机与传输对端）”，说明范围并提供本机 JSON 导出。没有上传接口，不持久保存到浏览器存储；刷新或关闭页面后记录消失。
- 本机每秒最多发起一次 `getStats()`／活动连接；最多保留 12 条连接记录，每条只保留最近 120 个样本。结束／取消后停止采样。较早的已结束连接在需要时移出记录。
- 通过既有加密 DataChannel 的 ping／pong，向当前传输对端附带匿名数值，单端单连接最多每 10 秒一次。不新增消息类型、连接或服务器请求；未启用的一端不记录、不回传这些数值。
- 不修改分块、读取、校验、压缩、收发窗口、写盘、重连或信令算法；不部署 Worker，也不增加 TURN。旧版本会忽略 ping／pong 的附加字段。

## 记录与解释

| 字段 | 用途与限制 |
| --- | --- |
| `generation`、`recovering`、连接／ICE 状态 | 观察是否重复重建连接。记录状态，不改变恢复时机。 |
| `confirmed`、`sent`、`recentBps`、`averageBps` | 区分最近实际进度与包含等待、重连的累计平均速度；近期速率使用相邻样本差值，短于 500 ms 的最后样本沿用前次近期值。 |
| `buffered`、`inFlight`、`queued`、`window` | 分别观察浏览器发送缓冲、应用未确认量、接收排队量和应用窗口。它们都不等于原生 SCTP 拥塞窗口。 |
| `sourceBytes`、`sourceReadAndHashMs` | 发送端既有累计指标，包含读取与 JS 校验，不是纯磁盘读取时间。 |
| `sinkBytes`、`sinkHashAndWriteMs` | 接收端既有累计指标，包含校验与写入，不是纯磁盘写入时间。 |
| `protocol`、候选类型、地址分类 | 观察 UDP／TCP、host／srflx／prflx／relay，以及私网／共享地址／公网／mDNS 分类；不保留具体 IP、端口、候选 ID 或 STUN URL。host 候选也不能单独证明物理局域网路径。 |
| `stunRoundTripMs` | 浏览器提供的候选对 STUN 往返值，不是 SCTP RTT，也不保证每秒有新的网络测量。 |
| `pairBytes*`、`pairPackets*`、`channelBytes*` | 浏览器提供的累计计数。候选对字节可能包含协议开销，不直接等于文件有效字节；这些计数无法直接给出丢包率或重传次数。 |
| `localSendDiscardedPackets` | 浏览器报告的本机发送丢弃数；不是端到端丢包率。浏览器未提供的字段省略。 |
| `nativeAgeMs` | 此缓存快照距离调用 `getStats()` 返回的时间，不是 STUN 探测值本身的年龄。 |
| `hidden`、`peerHidden` | 观察页面是否在后台；不读取其他应用。 |

`peer` 是对端最近一次附带计数，带有本端接收它时的相对时间 `peerAtMs`。短字段：`g` 连接代次，`s/a/r` 已送入通道／已确认／已写入字节，`b/q` 发送缓冲／接收排队，`rb/rm` 读取与校验累计字节／毫秒，`wb/wm` 校验与写入累计字节／毫秒，`bs/br/ps/pr` 候选对累计收发字节／包数，`h/x` 后台／恢复状态。对端计数受相同连接的延迟影响，不能把过期值当作当前值。

所有原生报告先经过字段白名单过滤；不保存原始报告、文件名、内容、分享密钥、房间号、候选地址、设备标识、浏览器 UA 或控制台日志。时间为相对值。对端输入只允许有限非负数，非法字段和数据被过滤；预览使用文本渲染。

## 如何判断下一步

1. 若读取与校验累计时间随低速显著增长，先调查源文件处理；不要直接归因运营商。
2. 若源读取很快、发送缓冲持续堆积、接收确认很少，调查实际所选路径和原生传输停滞。原生字节／包计数只能提供线索，不能单独证明丢包。
3. 若接收排队、处理耗时持续积累，调查接收校验／写盘。
4. 若连接代次频繁增加、恢复状态占据大部分时间，调查健康检查与恢复是否放大弱网问题。
5. 在实际移动数据的记录取得前，不调大窗口、不取消完整性校验，也不把合成实验当成真机结果。

验证覆盖隐私白名单、非有限数拒绝、默认关闭、定时器清理、历史上限、旧连接延迟结果隔离、双端／单端诊断兼容、真实文件独立 SHA-256 与原文件名、英文导出和窄屏布局。独立 WebKit 运行器不具备真实 DataChannel 能力的用例明确跳过，不能替代 iPhone 真机验证。
