# 慢网时才出现的压缩建议

平时没有压缩开关，也没有常驻的压缩设置。只有持续偏慢、两端支持、当前文件的抽样结果与设备计算速度表明值得压缩时，才在传输进度旁显示建议。发送方或接收方任意一端可以点击启用，也可以保持原样传输。

## 触发条件

以下条件同时成立才显示：

- 在前台且连接正常，最近的接收确认覆盖至少 8 秒，有至少 3 次进度增长；近期速度不高于 1 MiB/s（约 1.05 MB/s、8.39 Mbps）。采用最近约 12 秒的数据；极慢链路会延长窗口以保留三次确认，不使用页面上从开始以来的平均速度。回执按短时间桶合并，近期吞吐至少跨 2 秒计算，避免突发回执造成误判。
- 最近几次确认没有显示连接已经恢复高速。断线、后台切换重置观察窗口；没有进度的等待本身不能触发建议。
- 当前文件还有至少 8 MiB 尚未发送。已经发出的数据不重传、不重新压缩。
- 分别抽取尚未发送部分的开头、中间、末尾各 32 KiB，实际压缩。采用最差压缩率、最慢压缩速度。任一抽样压缩后仍超过原来的 85%，不再建议这个文件。
- 接收端实际解压一份 32 KiB 样本，返回耗时。源文件读取与校验、接收校验与写盘的处理速度不足当前确认速度的两倍时，也不建议；这只是对本机 I/O 瓶颈的保守筛查，无法完美分离网络、浏览器缓冲和存储耗时。
- 加上保守余量后，预计至少缩短 20%，且至少节省 5 秒。抽样只在已经测得慢网时才执行，每个稳定连接阶段、每个文件至多一次；断线或后台变化打断后，在重新观察后可再评估，探测之间至少间隔 15 秒。

用户拒绝后，这个文件不再重复提示。后续文件分别评估；一个接收者的选择不影响其他接收者。

## 公式

所有速率使用相同单位（例如 MiB/s），大小也使用对应单位。令：

- `R`：当前文件尚未发送的原始大小。
- `B`：最近实际确认的原始字节速率。普通传输时可近似为有效链路吞吐，不是物理带宽。
- `r`：三处样本中最大的 `压缩大小 / 原始大小`。
- `C`：实测发送端压缩速率。
- `D`：实测接收端解压速率。
- `P`：每个原始字节在两端读取、校验、写入上已经花费的时间之和（秒/字节）；这些工作不会因压缩而减少。

再取保守压缩比 `r′ = r + 0.05`、每字节计算成本 `k = 1.25 × (1/C + 1/D)`，以及固定切换开销 1 秒：

```text
普通传输预计耗时 T0 = R / B
压缩传输预计耗时 T1 = r′ × R / B + R × [k + (1 − r′) × P] + 1 秒
```

令 `K = k + (1 − r′) × P`，即把不变的原文件处理成本也保留下来。这里没有把流水线重叠带来的好处算进去；如果原文件处理成本已经占满有效吞吐预算，就不建议压缩。不是只比较压缩后文件大小。

如果仅要求有净收益，临界速度为：

```text
B < (1 − r′) / (K + 1/R)
```

结合产品的“至少省 5 秒、至少省 20%、本来就很慢”门槛，实际允许提示的临界值为：

```text
B ≤ min(
  1 MiB/s,
  (1 − r′) / (K + 6/R),
  (0.8 − r′) / (K + 1/R)
)
```

如果右边不为正，则没有值得提示的速度范围；还必须满足上文的持续观察、余量与兼容条件。1 MiB/s 是产品的“慢网”上限，不是所有文件统一的数学盈亏点。

例如剩余 100 MiB、当前 0.5 MiB/s，最差样本压到 50%，发送端压缩 20 MiB/s、接收端解压 50 MiB/s：若暂不计原文件处理成本（`P=0`），普通约 200 秒，保守压缩估算约 119.75 秒，预计省 80.25 秒；若原文件处理还需要合计 0.1 秒/MiB，压缩估算会增加到 124.25 秒，预计省 75.75 秒。照片、电影、ZIP 等已压缩内容通常没有足够空间，抽样不过关时，即使很慢也不显示压缩建议。

## 数据、续传与安全边界

- 使用浏览器原生 gzip，分块压缩。不是把多个文件打成 ZIP，接收端自动还原，仍以原始文件名保存。
- 每个原始压缩块最多 256 KiB，网络消息仍最多 32 KiB。不会先把整份文件压好，不增加整份压缩副本的磁盘占用。
- 同一文件可以先普通传输，用户启用后再压缩后面的部分。实际块压缩收益不足时发送原字节；连续三块不划算或压缩器异常时，回到普通传输。
- 继续对还原后的全部原始字节做 SHA-256；压缩流自身的 CRC 不能替代整文件校验。
- 自动配对断线仍以已经成功写入的原始字节位置续传。手动配对依旧不支持自动重连。未接收完整的压缩块直接丢弃，重新发送该块；不会从零开始。
- 解压前校验块大小、顺序、原始偏移，限制每个压缩块的碎片数量、以最多 1 KiB 的输入增量交给原生解压器，并在读取解压流时限制输出，不接受超出宣告大小的展开数据。截断、损坏、越界都不标记传输成功。
- 仅在双方声明支持 `gzip-block-v1` 时发送新增消息；旧页面仍按原协议传原始字节。
- 传输仍走现有 WebRTC / DTLS，不引入中继或文件上传服务。压缩只处理文件自身的独立块，不把配对密钥、认证信息或其他文件混入压缩上下文。

原生压缩行为以 [WHATWG Compression Standard](https://compression.spec.whatwg.org/) 为依据。

## 估算限制

抽样不能保证后面的每个块都一样好压缩，设备温度、后台限制和网络也会变化。提示文字使用“预计”；执行时会对每块检查实际压缩耗时和大小，未达到收益要求就发送原字节。此检查不是对实际端到端用时绝不变慢的保证。

本机浏览器的受控慢速测试不等于真实 iPhone / VPN / 跨国网络。
