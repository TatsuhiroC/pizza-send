# 常亮与后台返回恢复

## 使用行为

创建分享、等待首位接收者以及进行接收时，默认尝试保持屏幕常亮。状态区提供可关闭的「传输时保持屏幕常亮」开关，记住本机选择。只有实际拿到系统唤醒锁后，才显示已保持常亮；不支持、请求被拒绝、低电量或系统释放时，不宣称保护已经生效，并提供适当提示和重试入口。

切到后台时释放常亮锁，返回前台时尝试重新获取。取消、结束、失败及全部接收者完成时释放；多人分享使用整个页面的一把锁，一人完成不释放其他仍在传输的人的保护。后续新接收者加入时重新获取。不通过播放音频或申请麦克风权限保持后台运行。

自动配对的两端通过加密 DataChannel 交换页面是否位于后台。接收方先确认发送方支持这项扩展，避免向旧版发送方发送其不认识的消息。旧版页面仍能完成普通传输，但不具备新后台状态协作能力，双方刷新后才能完整使用。

页面仍在运行时继续传输；已知一端在后台时，暂缓通常的无响应／恢复超时，后台宽限最长 10 分钟，然后恢复普通失败处理。返回前台时刷新计时、检查连接，必要时恢复直连或加密转发，从接收方实际保存的位置继续。重新连接仍校验文件列表、续传位置、完整 SHA-256，保留原有磁盘流或内存。主动取消仍立即生效。

浏览器以 `pagehide.persisted = true` 暂存页面时，释放常亮锁和相机，但保留原文件、邀请和传输状态，不发送“结束分享”。从该缓存恢复时不强制刷新，重新检查配对连接和常亮状态；重复恢复事件合并成员查询。非缓存的页面离开仍清理会话。此行为不代表页面被系统回收后也能恢复。

## 边界

- 常亮仅适用于系统允许的可见页面，用户主动锁屏或切换 App 后不能保证继续传输。
- 后台宽限以收到页面状态为前提；系统可能来不及发送状态就终止页面。
- 页面被浏览器回收、刷新或彻底关闭后仍不能恢复未完成的传输。本次不新增持久化续传，不改变部分文件清理策略。
- 恢复仍需配对房间有效、服务可访问且网络能建立直连或加密转发；未改变邀请与房间的服务端期限。
- 旧版页面和手动配对没有自动恢复保证。
