# v0.2 Safari 磁盘暂存与清理

日期：2026-10-12。

接收流程保留桌面 Chrome / Edge 的原生保存位置选择。没有相应选择器时，先真实探测 Worker 中的 OPFS 同步文件访问和跨页面锁；能力可用则分块写盘，否则继续使用总计 256 MiB 的内存回退。

每次只转交一个 32 KiB 分块；写入完成后才推进接收位置和确认，传输队列与未确认发送窗口仍受限制。网络重连复用同一临时文件和增量 SHA-256 状态。完成校验、关闭写盘句柄并提交小型文件记录后才提供保存链接，直接使用磁盘文件对象，不拼接整个文件的内存 Blob。

完整暂存使用一个「已保存，清理全部暂存」按钮，确认文件数量和总大小后统一清理所有已接收的暂存，保留本地下载副本。下载无法提供可靠的完成通知，因此不会在点击保存时自动删除。整批接收结束（成功、取消或失败）后，已校验的完整文件获得 1 小时保存时间；活动传输不会因暂存计时而被清理。点击保存为该文件重新预留 1 小时，刷新、重新打开和列表检查不延长期限。页面保持运行时定时清理，到期后关闭或暂停的页面在下次打开或返回时清理。旧记录没有期限时从升级后首次打开获得 1 小时，不会立即删除。意外终止写盘进程时使用每个完整文件完成时已持久记录的期限。浏览器无法可靠报告下载完成，超过新预留的 1 小时仍在下载的文件不保证暂存继续保留。保存时可能同时占用暂存和下载两份空间。浏览器存储本身不保证长期保留，参见 [WebKit 存储策略](https://webkit.org/blog/14403/updates-to-storage-policy/)。

清理以确认框打开时的文件列表为准，新到达的文件需要再次确认。部分清理失败时可重试剩余文件；未完成的接收文件不会被清理。另一页面正在使用暂存时，先关闭该页面再清理全部。

取消和失败清理未完成的文件，同时保留之前已校验的文件。意外离开页面后释放写盘进程及跨页面锁，下次打开清理未完成残留。未完成传输仍不能跨刷新续传。不同接收会话和同名文件使用内部独立文件名，清理不会触及其他网站或用户的下载目录。正在另一页面使用的暂存会显示占用提示。

小型元数据轮流写入两份记录，降低更新被打断时丢失先前有效记录的风险；清理前更新两份记录，避免旧记录重新显示已经删除的文件。这不是对系统崩溃、设备故障或浏览器回收的持久保存承诺。

## 验证结果

| 环境与范围 | 结果 |
| --- | --- |
| 全套隔离浏览器回归 | 44 项通过，包含原有加密、配对、原生保存路径的 200 MiB / 1 GiB 和新增暂存路径 |
| 正式 WebRTC 接收流程，512 MiB，无保存选择器 | 实际磁盘暂存与导出，独立 SHA-256 一致；禁止接收页面进行整文件 ArrayBuffer 转换 |
| 真正的 Mac Safari 27.0.1，512 MiB | 隔离 Chrome 发送，使用已部署的 Cloudflare 服务配对；接收校验、刷新后保存、实际下载校验及界面清理通过，清理后下载仍保留 |
| 正式存储模块，隔离 WebKit，10 GiB / 20 GiB | 分块写入、完整文件记录、实际导出与独立 SHA-256 校验通过；不经过 WebRTC |
| 先前独立原型，真正的 Mac Safari，2 GiB / 20 GiB | 分块写盘、读回校验及实际保存通过，记录与正式集成测试分开保存 |
| 实际 iPhone Safari | 尚未实机验证大文件接收和保存，不承诺所有手机都支持 20 GiB |

Mac Safari 首次测试窗口出现内容不可见且无法操作的异常，该次会话未接收文件，未计为通过。新建测试窗口后页面正常，第二轮完成上述正式接收和下载验证。

新增回归覆盖重复文件名、空文件、Unicode、刷新与离开后返回、确认/取消清理、下载副本保留、跨页面活动文件保护、遗留部分文件清理、空间不足后重试、接收中写盘失败，以及后续文件校验失败时保留前面的完整文件。文件名、取消、消息队列和旧链接安全检查仍通过。

正式容量记录见 [WebKit 原始结果](../experiments/safari-storage/results/production-webkit.json)，实机集成记录见 [Mac Safari 原始结果](../experiments/safari-storage/results/production-safari-mac.json)。先前独立原型见 [验证页说明](../experiments/safari-storage/README.md)。容量和同机时间不能代表真实网络速度、iPhone 内存占用或 VPN 切换效果。

## 长时间传输的配对保活

首次邀请仍在 30 分钟后过期。双方客户端绑定后，认证心跳延长原会话的恢复期限，约每分钟更新一次，创建起最长 24 小时。邀请已过期时不允许新接收者占位；明确结束的房间不续期，旧的定时清理任务也会检查最新期限后再决定是否删除。

四项带模拟时钟的服务测试覆盖未配对不续期、原会话延长及 24 小时上限、旧定时任务和结束会话保护，以及邀请过期后的新接收者拒绝。实际网络恢复仍最多等待两分钟，需要双方页面打开、配对服务可访问和新网络可直连。文件内容不经过配对服务。
