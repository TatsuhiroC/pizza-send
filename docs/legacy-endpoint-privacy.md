# 旧配对入口隐私清理 · 2026-10-21

## 核对结果

审查基线为已发布的主分支 `f42ed18`。当前代码的旧配对地址迁移逻辑，以及测试夹具中的真实旧地址，包含可关联部署账户命名与姓名拼写的信息。两个参数化测试名称将这个地址带入了 Actions 日志。本次没有发现管理令牌泄露或账户接管证据；这个发现属于身份关联信息暴露。

正式网页配置已经使用 `https://signal.pizzasend.dpdns.org`。初次用隔离 Chrome 只读核对时，正式网页和配置返回 200；新旧配对入口均能返回 Worker 的 `Not found` 响应，确认旧入口当时仍在运行。配对 API 的根路径本来就没有文件传输或管理功能。

提供的日志定位报告标出了 43 次 PizzaSend 运行、86 行相关日志。本次再次读取其中最新和最早两次运行的日志，均确认存在两行地址输出。43 次是报告已观察到的范围，不能当作所有历史日志的完整普查。

## 当前修复

- 移除针对个人化旧地址的迁移判断。GitHub Pages 旧站已停用，正式网页也已换来源；新站不能读取旧站的浏览器设置，因此不再需要在新版本保留这段地址映射。
- 配对默认值继续来自 `app.config.json`；手动填写的自定义地址和留空的手动配对模式保持原意。曾主动填写旧入口的用户需要改用正式配对地址，这次清理不会擅自改写浏览器中的自定义配置。
- 测试仅使用虚构的自定义地址，并使用固定的描述性名称，避免将配置值写进测试标题。新增检查覆盖正式路由、关闭默认入口、没有具体 Worker 主机名的前端源码，以及 Chromium / WebKit 的设置行为。
- 将 `signal/wrangler.jsonc` 的 `workers_dev` 改为 `false`，保留自定义域名路由和已有 `preview_urls: false`。不更换 Cloudflare 账户子域，不改动其他项目或 Durable Objects。
- 更新中英文自行部署说明：仅使用默认 Worker 域名的自托管者，需要自行设置 `workers_dev: true`。

当前受版本控制的文件和新构建产物已核对，不再包含那个旧地址。前端通过合并到 `main` 发布；Worker 已单独部署，版本为 `da2225ef-17c1-449e-abc8-a3276c39d97d`。部署后复核旧入口返回 Cloudflare 的 404 停用页面，而正式配对域名继续返回应用响应。预览入口保持关闭。

## 历史处理边界

项目维护者明确批准后，逐一重新读取清单中的 43 次运行，确认日志包含旧地址，再单独删除对应日志。43 次全部删除成功，并逐一确认日志下载返回 404 / 410，运行记录、提交、完成状态、检查结论与检查套件标识保持不变。没有删除运行记录、检查结果或整个仓库。

当前源码清理和旧入口关闭都不会抹去旧 Git 提交、旧 PR 差异、历史构建产物或其他人保存的副本。重新运行旧提交的测试也可能再次输出旧地址。这里没有进行 Git 历史重写或强制推送；若以后确实需要移除历史版本，应另行确定范围、协作者影响和仍可获取的其他副本。

关闭入口仅限这个 Worker，不会对整个 Cloudflare 账户改名，也不会保证旧子域从历史记录或外部索引中消失。

## 官方操作依据

- [Cloudflare：在 Wrangler 中关闭 workers.dev](https://developers.cloudflare.com/workers/configuration/routing/workers-dev/#disabling-workersdev-in-the-wrangler-configuration-file)。配置需要实际部署才生效；默认入口与预览入口分别控制。
- [GitHub：单独删除工作流运行的日志](https://docs.github.com/en/rest/actions/workflow-runs#delete-workflow-run-logs)。删除日志与删除运行记录是不同操作。
