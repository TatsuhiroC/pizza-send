# 移动端打开分享与浏览器兼容排查 · 2026-10-27

本地修复草稿；未更新正式站、测试站或 Cloudflare 服务。

## 证据与判断

用户设备正常；其他人的 iPhone 和安卓出现点击分享链接或系统相机扫码后进入空接收页。另有荣耀手机与 Mac 双向连接失败的截图。不能把这些现象合并为一个已证实的根因。

| 现象 | 已确认的事实 | 尚不能确认 |
| --- | --- | --- |
| 微信阻止访问 | 微信截图进入了该域名的“申请恢复以下网页”流程 | 腾讯的具体判定原因、不同账号显示不同结果的原因；不能据此认定为免费域名或 Cloudflare 导致 |

## 本地修复

- 用 `AbortController` 与可清理定时器保留请求超时和外部取消，替代 `AbortSignal.timeout()`；安全重试仍仅用于允许重复的配对请求，创建分享不自动重试。
- 源文件检查不再要求 `AbortSignal.throwIfAborted()`；关键路径不再要求 `Array.at()`、`Object.hasOwn()`。编译语法降至 ES2020；不因此宣称支持所有旧浏览器。
- 加密依赖仍需 `Object.hasOwn()`，因此在依赖加载前提供标准等价兼容实现。保留自有属性、原型链、原始值与空值处理语义，不替换加密算法，也不增加第三方依赖。
- 浏览器必须具备 Web Crypto 和 WebSocket；缺少安全能力时明确说明，并保留完整邀请供用户换浏览器。真正缺少加密能力时不降级成明文。
- WebRTC 变成可选直连能力。没有 WebRTC、或者浏览器拒绝创建连接时，通过已认证的加密配对消息协商 WebSocket 转发。文件仍用既有 AES-GCM 和 SHA-256；不修改后端鉴权、票据、额度或加密格式。
- 不支持直连的会话禁用直连按钮，说明一端浏览器的能力限制；正常浏览器仍优先直连。
- ICE 消息应用前、跨异步调用后均核对连接实例和协商代次，忽略已关闭或被替换的连接；有效当前连接的实际候选错误仍会上报。
- 分享链接增加公开的接收用途标记；密钥仍只在 `#` 后。缺失 fragment 时提示完整链接丢失，绝不将密钥移进查询参数或服务器日志。
- 已打开页面收到新的邀请 fragment 时重新读取，正在进行的传输不会被另一邀请强行覆盖。
- 在配置加载或兼容失败时，把完整邀请放进接收输入框；收到真实文件列表后再清除地址栏邀请。
- 自动接收的连接状态及失败提示滚动到可见位置；连接信息处理异常不再一律标作“配对服务不可用”。转发协商与建立连接都有超时，避免没有 WebRTC 时失去原有 ICE 超时而无限等待。
- 脚本未能加载或解析时，HTML 自带双语加载及换浏览器提示，避免整页纯空白。

可供管理者核对后使用的说明：

这份说明不是对腾讯审核结果的保证。微信访问限制发生在网页执行前，网页自身不能解除该限制。

## 验证范围

使用生成数据、隔离浏览器与本机配对服务。复现记录保存在本地审查输出目录，未把截图中的实际分享密钥复制进源码或报告。验证项目包括：

- 旧超时 API 缺失、外部取消、超时和定时器清理；
- 初次打开、后续 fragment 导航、缺少配对信息、配置失败与安全能力不足；
- 关闭直连后迟到的 ICE，以及真正无效候选仍应报错；
- 无 WebRTC 的发送端、接收端、双方，以及构造器被浏览器禁止；检查传输密文、文件名和完整 SHA-256；
- 原有分享、配对鉴权、启动配置、路线切换和相关 WebKit 回归。

验证于 2026-10-28 完成：Chromium 85 项、WebKit 46 项、安全与密文通道 42 项、编译后旧 API 启动回归 2 项，共 175 项通过；另 1 项按现有引擎条件跳过。编译后的页面另外通过两个引擎的完整文件收发检查：同时移除上述旧 API、对话框关闭接口和 WebRTC，原文件名与独立 SHA-256 均一致。

旧运行时启动检查使用编译产物。Vite 开发客户端自身依赖新 API，直接删除开发环境的这些 API 会先使开发工具失败，不能作为产品兼容性的结论。相应回归已加入现有静态站点测试。

构建与公开文件检查通过；原始测试报告留在仓库外。组合构建中，固定的正式版入口脚本 SHA-256 与原正式版一致。本次未推送、部署或提交微信申诉。

本地模拟不能替代用户两台手机的最终验证，尤其不能宣称已经查明空接收页在真机上的唯一原因。
