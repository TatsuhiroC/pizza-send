# 浏览器兼容范围与检查记录

更新：2026-10-28。本轮为本地修复，未发布。

## 范围

优先保证目前使用的桌面 Chrome / Edge、安卓 Chromium 浏览器，以及 iPhone / iPad / Mac Safari。兼顾仍在使用的旧设备，不承诺兼容过去十年的所有浏览器，也不建议为使用本站而保留有已知安全漏洞的浏览器。

构建语法目标明确设为 Chrome 119、Safari 15.6；这是代码生成的边界，并不等于所有对应设备和内置浏览器均已真机认证。功能根据实际能力检测，不能只看浏览器名称或伪装的版本号。

| 能力 | 使用条件 | 不满足时 |
| --- | --- | --- |
| 自动分享与加密传输 | HTTPS、Web Crypto（AES-GCM、HKDF、SHA-256）、WebSocket、基本文件与流接口 | 明确提示换浏览器，保留完整分享邀请；不降级成明文 |
| 设备直连 | WebRTC 可创建、网络允许建立连接 | 双方通过认证配对协商端到端加密转发；无直连能力时禁用直连按钮 |
| 大文件本机暂存 | 模块 Worker、OPFS 同步访问句柄、Web Locks，实际写入和快照读回成功 | 使用既有内存接收上限（默认 256 MiB），不承诺大文件可收 |
| 剩余空间预估 | `StorageManager.estimate()` 可用 | 跳过辅助预估；真正写盘失败仍报告空间不足等错误 |
| 慢链路可选压缩 | 双方支持压缩流 | 保持正常传输，不推荐不可用的压缩模式 |
| 手动配对码 | 原有 PS1 gzip 格式，支持压缩流 | 提示使用自动分享链接或更新浏览器；不更改配对码格式 |
| 相机、剪贴板、系统分享、常亮 | 相应接口存在并获授权 | 保留粘贴 / 图片识别、手动复制、普通下载等既有退路；常亮不支持时提示 |
| 可选动画、布局观察器 | 相应接口正常 | 保留静态状态和基本布局，不阻断选择文件 |

Safari 15/16 的暂存和压缩行为与新版不同：Safari 16.4 修正同步访问句柄的控制方法，并加入压缩流；Safari 17 才完整支持存储额度查询。依据：[Safari 16.4 发布说明](https://webkit.org/blog/13966/webkit-features-in-safari-16-4/)、[WebKit 存储策略与 Storage API](https://webkit.org/blog/14403/updates-to-storage-policy/)。

## 本轮修复

用修复前的 Worker 原码独立复现了两项缺陷：异步控制方法导致探测清理失败；缺失额度查询导致创建暂存抛出 `TypeError`。前者会误退回有限内存接收，后者会直接中断暂存创建，不能由此推断所有用户遇到的连接失败都来自这两个原因。

1. 暂存和文件夹打包均等待 `flush / close / truncate / getSize` 的结果，兼容旧 Safari 返回 Promise 的实现。保持同步批量写入；不改变数据分片、ACK、传输窗口或密码算法。
2. 额度查询缺失或拒绝时跳过预估。仍保留实际磁盘错误和有明确额度时的事前检查。
3. 暂存探测验证真实快照内容，并设置 8 秒启动检测期限。Worker 消息解析错误会拒绝等待任务，避免接收无限等待。期限只用于能力检测，不用于实际传输写盘，也不在传输途中偷偷转为内存模式。
4. 可选布局观察器和 SVG 动画失效不阻断应用；相机保持既有完整画幅和固定后置镜头方案。
5. 复制接口缺失或被拒绝时尝试浏览器复制；仍失败则选中文本并提示手动复制，不误报成功。
6. 不支持压缩流时，手动配对显示明确替代方式；自动链接和加密转发不依赖压缩流。

没有新增运行时依赖或大体积兼容库。上一轮关于超时 API、无 WebRTC 转发、分享链接导航和启动失败的修复见 [移动端兼容排查](browser-compatibility-review-2026-10-27.md)。

## 验证方法与边界

- Chrome 138.0.7204.183 使用 Google 官方 Chrome for Testing 二进制；当前 Chromium 为 156.0.8078.4，WebKit 为自动化引擎 27.2。
- 构建后的页面在上述三个可运行引擎中完成生成文件的端到端加密转发，保留原文件名，独立 SHA-256 一致；同时关闭 WebRTC、压缩、暂存及部分可选新接口，页面无未处理错误。转发管线使用本机受控密文通道，并非公网 Cloudflare 性能测试。
- Chrome 119 官方二进制在当前 Mac 环境启动即退出，未进入页面，记为未验证；不据此认定网站不兼容 Chrome 119。
- Safari 15/16 特有的异步暂存方法、缺失额度查询等由能力模拟覆盖，底层仍用 Chromium / WebKit 真实 OPFS 写入、快照、重新打开及清理；不能代替历史 Safari 真机测试。
- 文件夹打包结果另由 Python 标准 ZIP 实现读取，检查目录、内容与校验，避免仅由同一套打包库自证。
- 原始报告保存在仓库之外；测试完成后清理下载的浏览器。不会将个人路径、实际分享密钥或浏览器二进制提交到 GitHub。

`file://` 直接打开源码 `index.html` 无法执行 TypeScript 模块。应使用开发服务器或正式 HTTPS 站点；这与设备浏览器兼容缺陷分别处理。微信的域名拦截发生在应用加载前，需要平台申诉，前端兼容修复不能解除拦截。

最终验证：Chrome 138 回归 54 项，WebKit 去重后 39 项，编译产物与版本隔离 8 项，共 101 项通过；包括 512 MiB 的真实落盘接收、导出和独立校验。另有三个可运行引擎的编译后完整加密转发检查通过。公开文件检查与构建通过；固定正式版入口脚本 SHA-256 保持一致。扫码动画测试曾使用写死的开发端口，已修正为当前页面来源并通过重跑。
