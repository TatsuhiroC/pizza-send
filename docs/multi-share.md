# 多人分享验证与设计

创建自动分享后直接显示二维码；同一个链接在创建后 30 分钟内允许多位接收者加入，最多同时接收 10 位。各人需要独立确认接收。发送端显示每人的连接状态、进度和速度；其中一人取消、断线或完成，不会结束其他人的传输。已完成后仍保留原来的链接和二维码，点击「结束分享」才关闭邀请与全部连接。手动配对仍是一对一。

文件由发送设备分别发送给每位接收者，不经过文件中继。并发共享发送设备的上传带宽，也增加其处理负担；不承诺十人并发的速度。各接收端使用自己的保存方式和容量限制，暂存仍在整批结束后保留 10 分钟。

自动分享使用父邀请房间登记成员，为每个随机接收会话派生独立子房间。HKDF 的 `PizzaSend/group/v1` 域与接收会话随机数派生子密钥，再使用既有分享派生方式生成子房间与接收凭据。文件连接仍使用 WebRTC DTLS，配对信息使用 AES-GCM；原文件名、内容和 SHA-256 校验保持不变。

只有持发送凭据并绑定同一浏览器会话的页面能获得成员列表及子房间发送凭据。接收者只能加入或退出自己的位置。邀请并不认证人的真实身份，应仅分享给预期接收者；持有链接的人可以接收文件。成员更新通过 WebSocket 推送，健康连接不轮询 HTTP 成员列表。

成员预留与十人上限在 Durable Object 事务中处理。退出或完成释放自己的位置；取消会阻止同一个接收会话晚到的加入请求。子房间冲突不能覆盖既有凭据，也不能在取消或过期时结束别人的房间；清理时原子核对归属。接收者在邀请最后一刻加入时立即取得恢复租期；续期保留原邀请截止时间，不能放行新的迟到接收者。主动结束优先于续期和晚到的子房间创建。

每个子连接独立复用原有两分钟恢复机制与已确认字节位置。页面刷新、关闭、系统回收和无法建立新直连的网络条件仍可能阻止恢复。父邀请和原有一对一房间 API 共存；旧三段链接继续可用。

2026-10-12 本地完整回归 65 项通过；最后补充的邀请边界和归属检查连同多人、二维码测试共 17 项通过。真实 Cloudflare 服务配对的 20 MiB、多文件、中文名称及独立下载 SHA-256 校验通过。Worker 部署版本：`256f353f-a5a8-48cb-b5f1-f3868f04b3fb`。

多人测试覆盖三位同时传输、一人同时中断传输和配对连接后续传、其他连接保持、完成后再加入、独立取消、结束所有连接、十人上限、位置释放、凭据隔离、邀请到期、最后一刻加入，以及房间创建/取消竞态。测试运行于同一台 Mac 的隔离 Chrome 页面；没有把这些结果当作跨公网测速、VPN 实测或十台设备并发实测。
