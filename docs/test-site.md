# 正式版与测试版

- 正式版：<https://pizzasend.dpdns.org/>
- 测试版：<https://pizzasend.dpdns.org/test/>

Cloudflare Pages 的生产分支仍是 `main`，构建命令改为 `npm run build:site`。每次 GitHub 主分支更新都会生成两份静态网站：根目录固定使用 `deployment/production.json` 中的完整 Git 提交，`/test/` 使用当前主分支。测试新功能只更新测试页；确认升级正式版时，明确修改生产提交，再发布。重新打开网页不会自动提升生产提交。

构建脚本从 Git 中提取稳定版本，使用它自己的锁文件构建；仅在锁文件完全一致时复用依赖。构建失败不会替换 Cloudflare 当前正常部署。源码检查依然用 `npm run build`；完整发布与路径隔离验证使用 `npm run build:site && npm run test:site`。CI 同时执行这两项。

测试版有醒目标记、简短版本号和返回正式版的链接，不允许搜索引擎索引，并关闭测试路径缓存。分享链接保留 `/test/`；测试时发送端与接收端都使用测试页。

当前新功能：[加密转发消息合并](stream-relay.md#测试版合并转发消息)。两端均支持时自动启用，文件仍小块读取；旧版对端维持原格式。生产固定提交不随此次测试发布提升。

测试构建通过编译常量隔离偏好设置、接收文件暂存目录、打包暂存目录及其锁名。测试页清理暂存不会清理正式版文件。两者仍是同一个浏览器来源，共享浏览器总存储额度；目录区分不是针对恶意同源代码的安全边界。当前测试页沿用正式配对／加密转发服务，各分享仍使用独立房间，服务额度共同计量。涉及后端协议或数据迁移的实验，需要另行准备兼容方案。
