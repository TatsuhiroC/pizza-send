# 服务端安全防护

## 目标与边界

配对信息由浏览器使用 AES-256-GCM 加密。文件优先走 DTLS 保护的 WebRTC；加密转发使用独立 AES-256-GCM 数据通道，见[转发设计](stream-relay.md)。服务端校验角色、一次性票据和资源额度。

域名和源码公开是正常部署方式。安全依赖不可猜的凭据、加密和服务端检查，不依赖隐藏地址。Origin 允许列表只是浏览器来源约束，不能认证任意客户端。

## 请求防护

| 范围 | 默认限制 | 执行位置 |
| --- | --- | --- |
| 全部 HTTP 请求 | 每 IP、每 Cloudflare 位置约 600 次/分钟 | Worker 原生限流，先于房间读取 |
| 创建请求 | 每 IP、每位置约 10 次/分钟；持久化计数再严格限制每 IP 10 次/60 秒 | 原生限流 + RateLimit 对象 |
| 查询 / 写入 / WebSocket 握手 | 每 IP、每位置约 180 / 120 / 90 次/分钟 | 先于房间读取 |
| 认证失败 | 每 IP、每位置约 30 次/分钟后，在该运行实例暂时阻止 60 秒 | 原生计数 + 有界内存缓存 |
| 新分享全局预留 | UTC 日 1,000 次、UTC 分钟 60 次 | 单个 Admission 对象事务 |
| 有效分享预留 | 128 个，每个分享最多 10 位同时接收 | Admission + 既有成员上限 |

原生限流是按 Cloudflare 位置的近似计数，不能当作全球精确用量账本；全局 Admission 则串行记录预留。已经创建的分享继续允许成员加入、已有连接认证、心跳和重连。配置错误或安全依赖不可用时拒绝创建/请求，不静默绕过防护。

创建请求体最大 4 KiB，已存在房间的 POST 请求体最大 2 KiB。格式校验和请求限流先于房间对象查找，创建的 IP 对象也受前置创建限流保护。既有 WebSocket 消息大小、队列和消息频率限制继续保留。

创建失败时释放有效预留，但已消耗的日/分钟预算不退回。释放需要匹配随机租约，不能释放另一分享。结束与到期清理释放名额，外部子房间清理失败由 alarm 重试；未能清理的预留最多 24 小时后在后续预留时移除。

这些限制减少存储和滥用成本，但请求进入 Worker 后才执行，因此**不能保证分布式攻击不消耗 Cloudflare 的免费 HTTP/DO 额度，也不是计费硬上限或无限 DDoS 保证**。到达提供商免费额度仍可能导致服务不可用。

## 条件验证

同一 IP 60 秒内前 3 次创建请求无验证，第 4 次起响应 428，页面才加载 Cloudflare Turnstile。完成验证后重试一次；初次请求和重试都计数。验证不上传文件，普通访问不加载该脚本。

服务器通过官方 Siteverify 检查成功状态、当前前端主机名、`create-share` action 和该房间的 cdata。伪造、过期、重复 token 由服务端/提供商拒绝。上游 5 秒超时，前端加载 15 秒超时、交互 2 分钟超时；失败和取消有明确提示，可稍后重试或用手动配对。无法访问验证域名时，高频创建会受到限制，正常低频创建不依赖它。

官方 token 为单次使用且最长 5 分钟：[服务端验证文档](https://developers.cloudflare.com/turnstile/get-started/server-side-validation/)。前端测试使用模拟组件，不自动操作真实 CAPTCHA。

## 凭据与日志

新版 HTTP 角色凭据置于 Authorization 请求头，WebSocket 使用随机 256 位票据，服务端仅存其 SHA-256 摘要。票据绑定房间、角色与 client，30 秒过期、事务消费一次。同角色/client 新票据替换旧票据，每房间最多暂存 8 张。长期分享密钥仍仅存在链接片段和浏览器内存中。

旧页面仍可使用旧 query 凭据，避免发布期间中断现有传输；这意味着尚不能承诺所有旧请求网址均没有角色凭据。后续移除兼容应另行安排版本窗口。

关闭 Workers 自动 invocation URL 日志；自定义日志仅汇总固定类别和分钟计数，无网址、IP、文件名、token 或解密内容。运行实例切换可能丢失未输出的当前分钟计数，统计不是精确审计账本。Cloudflare 作为基础设施仍可处理连接元数据；这不是匿名网络。

## 分享与信任边界

持有分享链接的人可以接收文件；链接和手动配对码必须保密，网页发布者与网页代码仍属信任边界。根据产品选择，已移除人工连接校验码及其生成逻辑，保留现有 DTLS、配对信息加密、文件完整性检查和服务端防护；没有增加取件码或发送端审批步骤。
