## 发现与修复

| 问题 | 影响 | 修复 |
| --- | --- | --- |
| 旧接收请求晚返回错误时，清理的是当前全局传输 | 用户取消连接后创建的新传输会被误关闭 | 用会话版本隔离旧请求；异步解码和手动应答只作用于原传输 |
| 文件夹选择途中失败后，已取得的部分文件句柄留在接收列表 | 重试选择新文件夹后，文件可能写到旧位置或对应错误位置 | 所有保存位置取得成功后才统一提交 |
| 文件夹接收只避免本批文件重名，未检查已有内容 | 已有同名文件会被覆盖，同名目录会导致接收失败 | 枚举现有条目，并对已有或本批同名文件自动添加数字前缀；名称比较忽略大小写 |
| 写盘或创建写入流的等待期间取消，晚返回操作仍更新状态 | 取消后仍产生进度或接收确认，晚创建的写入流未关闭 | 等待后再次检查取消状态，必要时中止写入流；结束后不发送接收确认 |
| 接收队列仅统计二进制字节 | 大量控制消息可在异步队列里持续占用内存 | 同时限制二进制、字符串和排队消息数量；进入队列前检查 |
| 粘贴链接和扫码链接的来源校验不一致；连接设置接受带凭据的网址 | 错误链接被误当成本项目链接，错误设置保存后才报错 | 使用同一网站来源与路径检查，保存设置时拒绝凭据和额外参数 |
| 浏览器阻止读取本地偏好时，初始化会中断 | 配对服务设置无法加载，并产生未处理错误 | 读取偏好失败时使用部署默认配置 |
| 已关闭的配对连接仍可安排重试；旧连接回调会影响心跳 | 产生多余定时器或干扰当前配对连接 | 关闭后不安排重试，旧连接关闭事件不清理当前心跳 |
| 文件名只按字符数截断，没有限制 UTF-8 字节长度 | 很长的中文名称、自动改名后的名称或跨平台不合法名称会导致保存失败 | 同时限制 UTF-8 与 UTF-16 长度，为数字前缀留空间；保留常见扩展名和完整 Unicode 字符，替换常见不合法字符与保留名称 |

前四个专项回归场景在修复前均失败，在修复后通过。保存保护使用真实浏览器 OPFS 文件句柄；旧请求隔离场景还完成了新会话的实际文件下载与内容检查。写盘取消和队列压力通过可控异步流与消息突发验证，属于协议边界测试。
