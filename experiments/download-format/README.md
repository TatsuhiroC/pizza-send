# 下载格式验证

开发服务器运行时访问 `http://127.0.0.1:5173/experiments/download-format/`，点击“生成验证文件”。页面使用正式磁盘暂存模块保存微型 MP4、PNG 和文本样本，同时提供旧导出方式和修复后的下载链接。测试页面不会包含在正式构建中。

内部暂存使用 `file-N.bin`，原始名称和类型保存在记录中。Safari / WebKit 的内部文件对象曾报告 `application/macbinary`；导出现在对磁盘对象使用带原始类型的 Blob 切片，保留文件引用，避免整文件读入数组。发送方类型为空或仅为通用二进制类型时，常见格式根据原扩展名补全；未知格式保持未指定。

2026-10-12：真正的 Mac Safari 与独立 WebKit 常规配置均导出 `.mp4`、`.png`、`.txt`，MP4 元数据（32×32、0.2 秒）和 PNG 解码（2×2）正常；MP4 与文本下载内容独立校验一致。Mac Safari 的旧方式没有复现追加 `.bin`，不能将此作为实际 iPhone 问题已经实机验证的证据。测试使用正式存储模块，不经过 WebRTC；实际传输的磁盘及内存导出另由 `tests/download.spec.ts` 覆盖。

独立 WebKit 验证使用临时常规浏览器配置。实际 iPhone 下载确认框和“文件”App 打开行为仍需用户复测。

微型 H.264 视频由 FFmpeg 的纯色画面生成，仅作为可播放测试样本；没有使用用户的文件。
