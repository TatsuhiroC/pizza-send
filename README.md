# 🍕 PizzaSend · 文件快传

**简体中文** · [![Read in English](docs/assets/language-english.svg)](README.en.md)

打开网页，把文件直接送到另一台设备。受 [FilePizza](https://github.com/kern/filepizza) 启发，独立实现。

**使用地址：[tatsuhiroc.github.io/pizza-send](https://tatsuhiroc.github.io/pizza-send/)**

选择文件 → 创建传输（自动显示二维码）→ 将同一个链接或二维码发给多位接收者 → 接收方各自确认接收 → 完成后点击「保存到设备」。发送页面和各接收页面需保持打开。

## 当前功能

- 多文件传输、分享链接、自动显示分享二维码；一次最多 100 个文件。
- 同一分享最多 10 位同时接收，每人独立连接、进度、校验与断点恢复。一人取消或断线不影响其他人；完成后仍可让后来的人加入。多人共享发送设备的上传带宽，并不会自动提高总速度。点击「结束分享」关闭全部连接。手动配对仍是一对一。
- 分享链接由三段随机信息缩短为一段 43 字符密钥；当前默认网址约从 241 字符缩短到 86 字符，旧链接仍可使用。
- 接收页支持后置相机扫描二维码，以及从二维码图片识别。扫码仅在本机进行；成功、关闭窗口或页面进入后台时停止相机，不申请麦克风权限。
- 长文件名按屏幕宽度显示省略号，点击名称弹出完整文件名；保存按钮独立，下载名称不因显示省略而改变。
- WebRTC 有序可靠 DataChannel，DTLS 加密文件直传。
- 32 KiB 分块，发送缓冲和接收确认双重流控；进度根据接收端确认更新。
- 增量 SHA-256 校验，确认文件完整后才显示完成。
- 桌面 Chrome / Edge 接收单个文件时选择保存位置后流式写盘；多文件接收和支持相关能力的 Safari 等浏览器使用 Worker 分块写入本机磁盘暂存，再逐个保存或点击“下载全部”。大小取决于设备空间和浏览器额度，没有统一的 20 GiB 应用上限；不支持写盘时仍使用内存缓存，总计限制 256 MiB。
- 未到期的已校验磁盘暂存可在刷新或重新打开本站后继续保存。暂存按文件实际接收完成的时间倒序显示，最新在顶部；旧记录按批次时间排序。顶部醒目的「清理全部暂存」按钮在确认文件数量和总大小后，一次清理全部已接收的暂存，保留下载副本。保存期间可能同时占用两份空间。整批接收结束后保留 10 分钟，到期自动清理；点击保存为该文件重新预留 10 分钟，刷新不续期。页面关闭或暂停时，下次打开或返回再清理过期文件。没有期限的旧暂存从首次访问获得 10 分钟；原来 1 小时的期限在升级后首次访问时缩短到最多再保留 10 分钟，更早到期的文件不延期。浏览器仍可能提前回收暂存，不保证最低保留时间。
- 取消或失败时清理未完成的暂存，保留之前已校验的文件；意外关闭后在下次访问清理未完成的残留。跨页面锁保护另一页面正在使用的文件。刷新后的未完成传输仍不能续传。
- 多文件接收不要求选择文件夹。桌面 Chrome / Edge 的“下载全部”逐个下载原文件；iPhone / iPad 的单个“保存到设备”和“保存全部”优先打开系统保存面板，可选择存储到文件、保存图片到相册或分享给其他 App。系统批量保存不可用或文件较大时，Safari 显示“逐个保存”，每次明确点击保存一个文件。全部方式保留原文件名与内容，不打包 ZIP。
- 自动配对持续增量交换连接地址（Trickle ICE），晚到的地址会继续补发，并区分等待发送方、寻找直连路径、链接占用和过期。
- 自动配对支持网络切换后自动重连、从接收方确认的位置续传；保留文件校验与保存位置。双方页面需保持打开。
- 可复制连接码手动配对，手动模式不依赖配对服务，暂不支持自动重连。
- 中英文即时切换，记住语言选择；桌面和手机布局，无第三方字体或统计脚本。

## 部署结构

前端是 Vite + TypeScript 静态网页，发布在 GitHub Pages。Cloudflare Worker + Durable Objects 仅转发配对消息，STUN 帮助发现连接地址。**文件内容不会经由配对服务传输或存储，没有 TURN 文件中继。**

正式配对入口为 `https://signal.pizzasend.dpdns.org`，域名由 DigitalPlat 注册、DNS 由 Cloudflare 免费方案管理，连接到原有 Worker。网页会自动使用新入口，包括曾保存旧默认地址的浏览器；自定义地址和留空的手动模式保持原设置。各地网络的可访问性仍需实测。

自动配对使用浏览器生成的 AES-256-GCM 密钥加密 SDP 信息。密钥在分享 URL 的 `#` 片段中，不随 HTTP 请求发给静态网站或配对服务；接收页面解析后清理地址栏。配对服务可见房间、角色、连接时间、网络地址和加密消息大小。房间角色令牌以 SHA-256 摘要存储，首次配对邀请 30 分钟过期；同一分享最多 10 位同时接收，每位接收者使用独立的连接房间、凭据和加密密钥。成员信息及每条连接的发送凭据只向认证发送端提供。主动结束分享会关闭邀请及其全部连接。配对连接意外断开时保留房间，允许同一浏览器会话重新连接，直到房间过期。

v0.2 中，首次配对邀请仍为 30 分钟；已绑定双方的会话随认证心跳延长恢复期限，最后一次续期后保留约 30 分钟，从创建起最长 24 小时。续期不会允许新的接收方使用已过期的首次邀请，也不会恢复已经结束的房间。

新版短链接的片段格式为 `#2.<43 字符>`。片段保留完整的 256 位随机密钥，用 HKDF-SHA-256 的不同标签在浏览器中派生房间号和接收凭据；创建房间时仅提交房间号和接收凭据的 SHA-256 摘要，不提交密钥。网页无需短网址跳转服务，也不会把密钥存到服务器。

分享链接持有者可以接收文件，应通过可信渠道分享。手动配对码包含网络连接信息，应同样保密。使用者仍需信任网页代码与发布者；这不是经过第三方安全审计的产品。

安全加固对创建、查询、写入、握手和认证失败分别限流，在访问房间存储前拒绝明显无效或超限请求。同一 IP 每分钟最多 10 次创建请求，第 4 次起需要服务端验证的 Turnstile；验证重试也计入请求次数。全局每天（UTC）最多 1,000 次创建配额预留，每分钟最多 60 次，最多 128 个有效分享预留；每个分享仍最多 10 位同时接收。全局限额只暂停新分享，不取消已有传输或恢复会话。

新版 HTTP 配对请求用认证请求头传递角色凭据，WebSocket 改用有效 30 秒、绑定角色和浏览器会话的一次性票据；为兼容旧页面，服务端暂仍接受旧 URL 凭据。自动请求网址日志关闭，仅保留不含密钥、IP、网址或消息内容的异常类别汇总。详见 [安全加固与验证记录](docs/security-hardening.md)。

首版不能保证任意两种网络都能直连。对称 NAT、UDP 限制、公司网络、VPN 路由和地域访问限制均可能影响连接；可先试同一 Wi-Fi。连接失败会显示错误，没有中继兜底。自动配对模式下，网络切换或暂时断线会触发重新收集连接地址、建立新的加密直连，再按接收方已写入的字节位置续传；最多等待两分钟。它会跳过已完成文件，保留当前文件的写盘流或内存数据及 SHA-256 状态，最终仍校验整个文件。恢复依赖配对服务可访问、房间未过期，并且新网络能直连；恢复时间和路线速度没有保证。网页关闭、刷新或浏览器释放页面后不能续传，手机锁屏可能触发这种情况。手动配对暂不支持自动重连。

连接排查时，双方先刷新网页并创建新链接；手机需停留在发送页面并保持解锁。同一 Wi-Fi 并不保证 VPN 下可直连，VPN 需要允许局域网和 WebRTC / UDP。可先关闭双方 VPN 验证，再比较开启 VPN 的结果。接收方主动退出或完成传输，会释放自己的接收位置；异常网络断开会保留位置用于原会话恢复。分享邀请未过期时，其他人仍可使用同一个链接加入；一人退出不影响其他接收者。

## 本地开发

需要 Node.js 22.12 或更高版本。

```sh
npm ci
npm run dev
# 另一个终端启动配对服务
npm run signal:dev
```

在网页「连接设置」填写 `http://127.0.0.1:8787`。留空即可使用手动配对模式。修改 `public/app.config.json` 可设置部署默认值。STUN 默认使用 `stun:stun.cloudflare.com:3478`，不会中转文件。

## 自行部署

1. Fork 仓库，并在 GitHub Settings → Pages 将 Source 设为 GitHub Actions。`main` 更新后先验证，再自动发布 `dist`。
2. 修改 `signal/wrangler.jsonc` 的 Worker 名字、`ALLOWED_ORIGINS`，填写自己的前端 origin。部署默认允许当前 GitHub Pages origin 和两个本地开发 origin。`routes` 中的自定义域名也需改成自己已在 Cloudflare 激活的域名；若只使用 `workers.dev`，删除 `routes`。
3. `npx wrangler login`，创建自己的免费 Turnstile 组件并添加前端主机名。将公开站点密钥写入 `TURNSTILE_SITE_KEY`，通过 `npx wrangler secret put TURNSTILE_SECRET_KEY --config signal/wrangler.jsonc` 保存服务端密钥；不要把密钥提交到仓库。然后 `npm run signal:deploy`。Durable Objects 使用 SQLite 存储，账号需支持此功能；用量和费用以 Cloudflare 账号额度为准。
4. 将返回的 Worker HTTPS 地址写入 `public/app.config.json` 的 `signalUrl`，提交并发布。Worker 更新需要另行部署，仓库中不保存访问令牌。

## 验证

```sh
npm run build
npx playwright install --with-deps chromium webkit
npm test
npm run test:webkit
npm run signal:check
```

浏览器测试覆盖真实 DataChannel 自动/手动配对、20 MiB 多文件下载与独立 SHA-256 校验、空文件、中文文件名、损坏拒收、取消、来源限制、加密消息篡改和响应式布局。大文件测试把 200 MiB、1 GiB 文件写入真实浏览器 OPFS 磁盘流，完成后重新读取并独立校验；它替代了原生保存窗口，不是系统保存窗口的自动化验证。

测试只在隔离浏览器中使用虚拟媒体设备，帮助暴露本机 ICE 接口和验证视频扫码。应用只有在用户点击扫描按钮后才申请相机权限，不调用麦克风。自动化测试的同机耗时不能代表跨设备或互联网速度，也未证明相对 FilePizza 的速度提升。

多人测试覆盖三人同时传输、其中一人连接和配对同时中断后续传、其他人不中断、完成后再加入、原文件名与独立 SHA-256 下载校验、独立取消、十人上限和位置释放、凭据隔离、邀请到期以及取消与房间创建的竞态。多人测试运行于同一台机器的隔离 Chrome 页面，尚未验证十台实机并发。

恢复测试覆盖连续两次连接中断、配对连接同时中断、磁盘流保持、完成确认丢失、非法续传位置、恢复后的损坏拒收和恢复期间取消。它们强制中断隔离浏览器的真实连接。自有配对域名上线后，用户反馈无 VPN 收发和传输中关闭 VPN 续传正常；这仅代表其设备和网络，不代表所有 VPN 或跨网络组合均已验证。

详细结果见 [首版验证记录](docs/validation.md) 和 [代码审查记录](docs/review.md)。

v0.2 首次集成的 44 项回归还覆盖正式 OPFS Worker 接收与实际导出 512 MiB、刷新和返回页面后的再次保存、重复文件名、空文件、确认清理后下载保留、跨页面保护、残留清理、空间不足重试、磁盘写入失败和多文件部分失败。512 MiB 测试禁止接收页面把整个大文件转换为 ArrayBuffer，导出后独立校验。

真实 Mac Safari 27.0.1 已通过正式流程接收 512 MiB：使用已有 Cloudflare 服务配对，刷新后仍能保存，下载后的 SHA-256 一致，界面清理暂存不删除下载副本。正式存储模块也在隔离 WebKit 中通过 10 GiB / 20 GiB 分块写盘与实际导出校验；容量测试不经过 WebRTC。先前 Mac Safari 2 GiB / 20 GiB 独立原型结果另外保留。**iPhone Safari 大文件接收和导出尚未实机验证，不承诺每台手机都能接收 20 GiB。** 详见 [v0.2 验证记录](docs/safari-storage.md)。
